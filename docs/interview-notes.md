# 面试笔记

给这个项目写一份"被追问时怎么答"的底稿。每条都对应仓库里的一段代码，方便现场翻。

## 一句话介绍

> 一个分诊优先的智能问诊系统：红旗症状由确定性规则在任何模型调用之前拦下来，其余问题走"路由 → 检索 → 作答 → 病史抽取"，每条结论都能追到指南片段。

## 三个必讲的设计决定

**1. 为什么把安全做成闸门，而不是提示词？**

提示词是不可验证的约束——你无法证明模型下次也会遵守。规则可审计、可测试、零延迟，而且能在任何模型进入之前把急症拦下来。代价是规则会漏，所以语义层只能**升级**严重度、不能降级（`merge()`）。代码：`backend/app/safety/rules.py`。

**2. 为什么检索放在生成之前，而不是给模型一个搜索工具？**

让"模型是否检索"从概率事件变成确定事实。副作用是引用可以校验（越界编号直接删除）、延迟可预测、失败可观测（`ungrounded_answer` 标记）。代价是模型不能自己发起第二次更精确的检索——在 70 个片段的语料上，这个代价可以接受。

**3. 为什么护栏是句级的？**

流式场景里事后过滤没有意义：字已经在用户屏幕上了。`SentenceGuard` 缓冲到句末标点再放行，命中药名+剂量、确诊式表达的句子在发送前替换。代价是首字延迟多一个句子（约 0.3–0.8 s）。

## 可能被问到的问题

**Q：多智能体比单智能体到底强在哪？你们的评测不是打平了吗？**

答案质量确实接近（judge 4.06 vs 4.44，三轮波动 0.2–0.4）。差异不在"写得好不好"，而在三件单智能体没有的事：急诊路径 0 ms 且不经过模型、信息不足时 100% 追问、引用编号可服务端校验。如果只比一段文字的质量，单 Agent 完全够用——多 Agent 的价值是把"该谁说话"从提示词里拿出来，变成可观测的结构。

**Q：怎么防止模型乱开药？**

三层：提示词约束 → 句级护栏（`guard.py`，正则拦药名+剂量、剂量调整、确诊断言）→ 评测集里的对抗用例（`must_not` 列表）。护栏是兜底，不是唯一防线。

**Q：LLM 延迟高怎么办？**

先量再调。测量结果：`thinking` 默认开时 TTFT 4.65 s，关掉 0.59 s；把 `max_tokens` 从 900 提到不设上限，曾出现 38 s 的单轮（思考 token 占大头）。现在：问诊关思考、320 token；全科关思考、800 token + 180–260 字硬约束；路由用 flash。另外两处省时间：调度走规则快路径、病史抽取与回答并行。

**Q：为什么用 PydanticAI 而不是 LangGraph？**

参考项目是 LangGraph Supervisor，我换掉的原因是流式语义——这一轮要同时做"逐句护栏"和"结构化旁路"，需要完全控制每个事件的产生时机，框架的图流式反而碍事。PydanticAI 提供类型化输出和依赖注入，编排我自己写成显式状态机（`pipeline.py`），可测、可读、没有隐藏魔法。

**Q：检索为什么不用向量库？**

70 个中文片段，字符 n-gram TF-IDF 对「低密度脂蛋白」这类术语比小稠密模型更稳，而且零下载、零 GPU、结果可复现。代码里留了 `EmbeddingProvider` 接口，语料上到几百篇时可以直接换。

**Q：数据合规怎么考虑？**

演示项目：单租户、本地 SQLite、不接任何真实患者数据，语料是公开指南的要点摘要。真实部署需要行级安全、字段级加密、审计日志和数据处理协议——README 的「已知限制」里写明了。

**Q：这个项目最难的部分是什么？**

不是接模型，是**让系统在不确定时仍然说人话**：检索没命中要不要说？模型超时怎么收尾？信息不够是追问还是先给方向？这些决定最后都落在结构化契约上（`RouteDecision` / `IntakeExtraction` / `ReportNarrative`），而不是散落在提示词里。

## 可以现场演示的三条路径

1. 「最近总是头晕，早上起来尤其明显」→ 只问一个问题，右侧槽位从 0% 涨到 33%。
2. 「我爸胸口压着疼，满头大汗」→ 红色横幅 + 120，耗时 0 ms（看 `/insights` 的紧急计数）。
3. 报告页 → 指标表 3 项偏高 → 「可以问医生的问题」。
